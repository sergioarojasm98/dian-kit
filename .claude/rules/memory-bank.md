# Memory Bank Rules

## When to Update

When the user asks to "update the memory bank":

1. Review what was worked on in the current session
2. Update `active-context.md` with the current state (ALWAYS)
3. Update `task-tracker.md` moving tasks between states (ALWAYS)
4. If there were architecture changes, update `system-patterns.md`
5. If new technologies/dependencies were added, update `tech-context.md`
6. If scope/objectives changed, update `project-brief.md`

## Update Format

- Use the current date in `active-context.md`
- Keep lists with checkboxes `[x]` / `[ ]`
- Use tables for decisions
- Do not repeat information across files

## Anti-Patterns

- Do NOT document plans as if they were facts
- Do NOT leave `active-context.md` outdated at the end of a session
- Do NOT add information that already exists in another memory bank file
- Do NOT make code changes without reading the memory bank first
